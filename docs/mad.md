# mad для windows x64

база: telegram desktop v7.4.2 и tele `febf332de00c33af585d9bd316782b320a6bdf67`: 335 патчей клиента и 7 патчей lib_ui. собственные изменения идут после исходной очереди. из tele 24 и tele 25 взяты исправления и функции, они перечислены в разделах «что взято из tele 24» и «что взято из tele 25». сервер b.mad.tg и ios-клиент не изменяются.

## сборка

папки `mad`, `tdesktop`, `Libraries` и `ThirdParty` должны лежать рядом. нужны visual studio 2022 build tools с msvc 14.44, windows sdk 10.0.26100.0, python и зависимости из инструкции tele.

1. примени очередь в чистом tdesktop v7.4.2: `python tele.py checkout` из папки `mad`. команда не требует `--force`.
2. подготовь зависимости командой из `docs/building-win-x64.md` в tdesktop. используется изменённая очередью версия wallet-engine; старых библиотек официального клиента недостаточно.
3. выполни `python configure-mad.py`. api_id и api_hash вводятся локально; hash скрыт. временный файл удаляется после configure. cmake сохраняет значения в локальном, исключённом из git каталоге `tdesktop/out`; не публикуй его кеш и диагностические дампы.
4. для debug выполни `python build-mad.py`. для оптимизированной сборки сначала выполни `python prepare-mad-release.py --jobs 4`, затем `python build-mad.py --config Release`. подготовка сохраняет debug: qt получает отдельные исходники и установку; остальные библиотеки собираются в имеющихся release-конфигурациях. результаты: `../tdesktop/out/Debug/mad.exe` и `../tdesktop/out/release-build/Release/mad.exe`. число потоков можно изменить через `--jobs 4`.
5. тесты адаптера, шифрования и слияния правок: `python build-mad.py --config Release --tests` (для debug убери `--config Release`). перевод: `python ci/check-translations.py`.

локальная сборка собирается с `DESKTOP_APP_DISABLE_AUTOUPDATE=ON` и `TELE_BUILD=0`, поэтому сама не обновляется. релизы из actions получают номер из тега и обновляются по подписанному фиду `mad-update-win64.json` из релизов этого репо. однофайловый `mad.exe` не откатывает обновлённый клиент: апдейтер оставляет рядом с exe файл `mad.exe.updated` с его хешем.

## изменения текущей сборки

настройки mad находятся в отдельной секции вверху списка настроек и в последней секции бокового меню. бейджи, сервер, резервные копии и обновления вынесены в категории. скрепка открывает описание настройки, не переключая её. название mad не переводится; история выпусков начинается с mad 1 и не загружает архив tele с github.

у бейджа добавлен отдельный отступ от premium/verification. отсутствующая картинка проверяется на диске один раз, а неизменные назначения больше не вызывают полное обновление имён каждую минуту. для проверки задержек подготовлена отдельная release-конфигурация; снижение лагов нужно оценить вручную.

сервер алиасов и истории находится в [server](../server/README.md). он развёрнут на `https://sync.mad.tg`, с https и ежедневными резервными копиями. подключение описано в инструкции сервера. штатные тесты node проверяют шифрованный обмен, подмену, изоляцию хранилищ, отзыв устройства, etag, лимиты, повторные запросы и перезапуск sqlite.

синхронизация выключена по умолчанию и включается отдельно для аккаунта. адрес сервера подставляется автоматически. выбери файл подключения и сохрани файл переноса с мастер-ключом. сохранение подключения не включает отправку. при включении также включаются локальное сохранение удалённых сообщений и история правок. их дополнительные фильтры и сроки хранения задаются в разделе сообщений.

мастер-ключ создаётся локально, хранится в зашифрованном хранилище аккаунта mad и не отправляется на сервер. код переноса содержит секреты: мастер-ключ и серверный токен. для раздельного отзыва устройств создай каждому свой токен. локальный индекс доставки содержит только hmac, не текст и не идентификаторы сообщений. импорт проверяет аккаунт, шифротекст и формат; конфликтующие версии правок объединяются. большие архивы экспортируются порциями по 16 записей.

ограничения: файлы вложений не переносятся, но их метаданные и подписи сохраняются. старые ссылки telegram на вложения могут истечь. перенос между двумя вошедшими аккаунтами и поведение интерфейса вручную не проверены. сообщения, которые ни один клиент не успел сохранить, восстановить нельзя. локальная очистка не удаляет облачный архив. после смены срока хранения можно нажать «скачать историю заново».

## данные и настройки

у debug-сборки данные находятся рядом с exe, в `tdata`. если эта папка недоступна для записи, используется `%APPDATA%/mad`. установленная телега и tele имеют другие каталоги. существующие сессии автоматически не переносятся.

в настройках раздел называется `mad`. ключи `tele-*`, внутренние пространства имён и старые ссылки `tele/...` сохранены для совместимости экспорта. бейджи mad и строчные буквы включены по умолчанию; прочие значения наследуются от tele.

русский каталог лежит в `Telegram/Resources/langs/mad_ru.json`. `Tele::Tr` переводит только явно переданные строки интерфейса, до `.arg(...)`. `Tele::TrCount` выбирает одну из трёх русских форм. пользовательский текст и содержимое реестра не проходят через этот переводчик. английский используется для остальных языков.

## бейджи

`tele_mad_registry` проверяет ed25519-подпись исходных байтов payload, схему 1 и key id `mad-badges-1`. публичный ключ взят из проверенного клиента madgram: `fu30bgNFntwaeXWD3dyTuMgWKM12eGKgqwRbgl/Soy0=`. числовые id разбираются как 64-битные целые без промежуточного преобразования в double.

`tele_mad_badges` запрашивает `https://b.mad.tg/api/v1/registry` при запуске и раз в минуту. картинки допускаются только с https-хоста b.mad.tg, из `/assets/`; единственный допустимый query-параметр `v` должен совпадать с подписанным хешем картинки. проверяются sha256, формат webp, размеры 64/128 и предел ответа 2 мб. кеш картинок ограничен 25 мб.

последний проверенный реестр хранится в `tdata/mad_badges/registry.json`; etag связан с хешем этого файла. повреждённые ответы и более старые ревизии не заменяют рабочий реестр. срок действия проверяется при отрисовке. production-назначения не используются в тестовых аккаунтах telegram.

отключение бейджей останавливает запросы и скрывает их. доступны обновление вручную и очистка кеша. флаги `-teleoffline` и `-noteleserver` запрещают загрузку, оставляя доступным проверенный локальный кеш. адрес совместимого сервера по умолчанию — `https://sync.mad.tg`; свой непустой адрес сохраняется. при открытии окна синхронизации пустой адрес заполняется автоматически. отправка истории остаётся выключенной до явного включения для аккаунта.

debug x64 успешно собран msvc 14.44: `tdesktop/out/Debug/mad.exe`, около 607 мб. предыдущая сборка запускалась: стартовый экран и заголовок mad отображались. текущая сборка после исправлений интерфейса и добавления синхронизации не запускалась по твоей просьбе. до запуска каталога данных не было; клиент создал отдельный `out/Debug/tdata`. при запуске сам загрузил реестр и etag в `tdata/mad_badges`; сохранённый ответ прошёл проверку production-подписи отдельным тестом. оба апдейтера отключены.

1. войди в аккаунт и выбери русский язык. в настройках → mad проверь перевод, поиск и отсутствие обрезанных подписей.

5. проверь светлую и тёмную темы, другой масштаб windows, apple-эмодзи и кастомные эмодзи. отдельно пройди режим призрака, папки, инструменты, скрипты и экспорт/импорт настроек. существующий ayugram/telegram должен работать со своей сессией независимо.

## проверка нового расположения настроек

mad выделен отдельной секцией вверху настроек. в боковом меню пункт расположен в последней отдельной секции: пкм → убрать из бокового меню. вернуть можно через настройки → mad → интерфейс → боковое меню.

названия опций переносятся на несколько строк; значения текстовых настроек показаны под названием. отдельные строки «об этой настройке» удалены: описание открывается скрепкой в строке самой функции. наведение с задержкой 350 мс показывает короткую анимированную подсказку, клик — полное описание.

для проверки открой настройки при узком окне, проверь длинные строки в разделе «отправка», наведи мышь на скрепку и нажми её. проверь пкм на пункте mad в боковом меню, его скрытие и восстановление. проверь светлую/тёмную тему и масштаб windows. эти проверки оставлены пользователю, клиент автоматически не запускался.

иконка скрепки кешируется с учётом цвета и масштаба, общие строки интерфейса — с учётом исходного текста и режима строчных букв. кеш перевода сбрасывается при смене языка/регистра. ускорен путь обработки обычных строк без ссылок и служебных тегов. влияние на реальные задержки переключения чатов, папок и настроек пока не измерено; для этой проверки предназначена release-сборка.

## запуск release с текущим аккаунтом mad

`start-mad.cmd` запускает `tdesktop/out/release-build/Release/mad.exe` с явным `-workdir`, указывающим на существующий каталог `tdesktop/out/Debug`. так release использует уже созданные данные mad без копирования и переноса сессий. перед запуском закрой другую сборку mad. скрипт предназначен для текущего локального расположения папок.

release x64 успешно собран msvc 14.44 с оптимизацией скорости: `tdesktop/out/release-build/Release/mad.exe`, 296306688 байт (около 283 мб). qt собран отдельно с оптимизацией и отладочными символами (relwithdebinfo); сам клиент — release. оба апдейтера отключены. в release прошли `mad_registry_tests` и `mad_history_crypto_tests`; проверки остаются активными при отключённых debug-assert. каталог перевода также проверен. клиент не запускался, плавность и интерфейс проверяются вручную.

release отдельно разрешён пользователем для проверки общих задержек. это отменяет ограничение agents.md на debug для этой сборки, но не подтверждает устранение лагов без ручной проверки.

## меню сообщений и профиль

действия бывшего подменю tele показываются прямо в контекстном меню сообщений, в том числе при ранее сохранённой раскладке меню. при выделении сообщений рядом с «переслать» доступна кнопка «снимок», если включена функция shot. она работает в обычном чате, ответах и закреплённых сообщениях.

в меню профиля пользователя или бота добавлен пункт «скрыть сообщения пользователя» и обратное действие. скрытие действует в личном чате и группах, сохраняется в списке игнорируемых и не меняет режим остальных участников этого списка. для собственного профиля пункта нет. сервер telegram сообщения не удаляет.

ручная проверка: выдели несколько сообщений и сделай снимок верхней кнопкой; проверь отсутствие промежуточного tele в пкм; скрой сообщения пользователя через профиль, проверь личный чат и общую группу, затем верни их тем же пунктом. отдельно проверь узкое окно и масштаб windows.

после добавления меню профиля и верхней кнопки снимка release пересобран успешно. экспортированный патч 344 применён поверх повторно проверенной очереди 343; итоговые git tree корневого репозитория и lib_ui совпадают. серверные тесты и публичный зашифрованный обмен после перезапуска прошли. новая сборка клиента не запускалась.

## упрощённое подключение и выделение

в окне синхронизации есть пошаговая инструкция, выбор файла подключения и сохранение файла переноса. кнопка «подключить» обрабатывает вставленный вручную код; выбранный файл применяется сразу. до подключения тумблер неактивен. файл переноса содержит адрес сервера и мастер-ключ: второй пк получает их автоматически из файла. загрузка истории остаётся добровольной.

кнопка снимка показывает число выделенных сообщений и обновляет ширину при изменении числа. пункт локального имени называется «изменить имя для себя…».

при включённом «выбрать несколько чатов» в пкм обычного списка чатов появляется «выбрать чат» / «снять выделение чата». после первого выбора остальные чаты добавляются обычным кликом; shift выбирает диапазон, alt продолжает работать как раньше. выход — крестик панели выбора или escape. поиск сообщений и темы форума не получают этот пункт.

ручная проверка: загрузить connection.json, сохранить файл переноса, включить и выключить синхронизацию; проверить первый запуск и собственный адрес сервера; изменить число сообщений с 9 до 10 и обратно; выбрать и снять несколько чатов по пкм и кликом, затем выключить опцию и проверить обычное открытие чатов.

патч 345 экспортирован и повторно применён к проверочной очереди на v7.3.3; итоговые деревья совпали. release x64 пересобран успешно, оба апдейтера отключены. новые диалоги и выбор чатов вручную не запускались.

## быстрые режимы и выбор иконок

в боковом меню есть тумблеры режима призрака и режима стримера, в трее — действия включения и выключения с текущим состоянием. пкм по боковому тумблеру позволяет скрыть его; вернуть можно в настройках mad → приватность → соответствующий режим. при блокировке клиента локальным паролем быстрые действия в трее скрыты.

## единый exe и приветствие

`python package-mad.py` создаёт `Downloads/mad.exe` из готовой release-сборки. нужны установленный 7-zip и msvc 14.44. модуль распаковки lzma sdk 26.05 загружается с официального github-релиза и проверяется по фиксированному sha256; `--sdk <файл>` позволяет использовать заранее скачанный архив. упаковка включает только mad.exe, графическую библиотеку, лицензии и небольшой нативный запускник. сессии, пользовательские настройки, pdb и ключи синхронизации не включаются.

после первого входа в аккаунт на этом пк появляется локальное приветствие от mad с расположением настроек и пояснением про синхронизацию. сообщение не отправляется через telegram. состояние показа отдельно для production и тестовых аккаунтов хранится в `tdata/mad_welcome`; при следующих запусках оно не публикуется заново. механизм не зависит от `TELE_BUILD=0` и не включает автообновления. как и исходный локальный чат tele, сообщение не хранится в облачной истории.
