# сборка mad в actions

сборку и релизы делает [.github/workflows/build.yml](../.github/workflows/build.yml). остальные задания tele удалены: автоматической синхронизации с upstream и публикаций в чужие каналы нет.

## настройка

в форке actions выключены по умолчанию: включи их во вкладке actions.

в settings → secrets and variables → actions добавь три repository secrets: `TDESKTOP_API_ID` и `TDESKTOP_API_HASH` своего приложения telegram и `MAD_UPDATE_KEY`, закрытый ed25519-ключ подписи фида обновлений в pem. его открытая часть лежит в `ci/update-public-key.pem` и вшита в `tele_updater.cpp`. потеряешь ключ, и уже установленные клиенты не примут новые обновления. не добавляй их в yaml или исходники. workflow получает их только в шагах проверки и конфигурации; артефакты не включают cmake cache, логи сборки, pdb и профили.

## запуск

actions → mad windows release → run workflow. оставь tag пустым для автоматического `v7.3.3-mad.<номер запуска>` или укажи новый тег этого формата. publish после успешной сборки отдельным заданием на ubuntu подписывает фид `mad-update-win64.json` и публикует релиз как последний (latest), откуда его забирают клиенты. ключ подписи в задание сборки не попадает. выключенный publish оставляет только actions artifact на семь дней.

существующие релизы не перезаписываются. workflow закреплён на windows-2025 и конкретных коммитах actions. подготовленные библиотеки сохраняются в кеш сразу после подготовки, даже если дальше сборка упадёт, и перед этим очищаются от исходников и промежуточных файлов, как у tele. сам клиент собирается через ninja с ccache: скомпилированные файлы тоже лежат в кеше actions (до 3 гб) и сохраняются даже после упавшей сборки, так что следующий прогон компилирует только изменённое. файлы с `__DATE__` и `__TIME__` всегда компилируются заново, чтобы дата сборки была верной. чистая первая сборка может занять несколько часов. лимит задания — шесть часов.

## результат

- `mad.exe` — единый распространяемый файл с проверкой распаковки, повторного запуска, восстановления повреждённого компонента и сохранности профиля.
- `mad-v7.3.3-mad.<номер>-win64.zip` — mad.exe, библиотека direct3d и лицензии.
- `SHA256SUMS` — хеши exe, zip и манифеста.
- `source-manifest.json` — коммит очереди, дерево собранных исходников, подмодули и хеши патчей.

тесты проверяют диплинки, подписи бейджей, криптографию истории и сервер. перевод проверяется на пропуски и повреждённые подстановки. runner не входит в telegram и не проверяет интерфейс с реальным аккаунтом.

сборка получает `TELE_BUILD` из номера тега (`v7.3.3-mad.N` → `N`) и `DESKTOP_APP_DISABLE_AUTOUPDATE=ON`: апдейтер telegram выключен, апдейтер mad сравнивает `AppVersion` и `N` и ставит только подписанные сборки из релизов этого репо.
