# memory

память проекта для людей и ai-агентов: как устроен mad, где что лежит и какие решения уже приняты. правила кода и патчей у tele в [AGENTS.md](AGENTS.md), здесь только то, что относится к mad.

## что это

- mad это форк [tele](https://github.com/nitreojs/tele): очередь патчей поверх telegram desktop. репо [yar2slav/madgram-desktop](https://github.com/yar2slav/madgram-desktop) это гитхаб-форк tele, `upstream` у локального клона смотрит на nitreojs/tele
- тег telegram desktop лежит в `UPSTREAM`, патчи в `patches/tdesktop` и `patches/Telegram/<сабмодуль>`
- свои патчи mad идут в конце очереди, у каждого строка в таблице [docs/releases.md](docs/releases.md) в секции `mad dev`
- только windows x64

## локальная сборка

- папки лежат рядом: `mad`, `tdesktop`, `Libraries`, `ThirdParty` (у ярослава это `Desktop\tgbuild`)
- `python tele.py checkout` из `mad` ставит tdesktop на тег из `UPSTREAM` и применяет очередь коммитами на ветке `tele`
- правки делаются коммитами в дереве tdesktop, потом `python tele.py export`. патчи руками не правятся
- release собирается `python mad/build-mad.py --config Release`, тесты добавкой `--tests`. результат в `tdesktop/out/release-build/Release/mad.exe`
- после смены тега в `UPSTREAM` надо заново прогнать подготовку библиотек: `tdesktop\Telegram\build\prepare\win.bat skip-release silent` и `prepare-mad-release.py`, это час-два

### грабли

- русская visual studio ломает configure у ffmpeg. нужен английский языковой пакет вижлы и `VSLANG=1033`
- `git add -A` в корне tdesktop цепляет указатели сабмодулей, и тогда `tele.py export` отказывается. в корне добавлять только свои файлы, правки сабмодулей коммитить внутри сабмодуля
- `tele.py export` не работает при незакоммиченных правках в tdesktop. чужую незаконченную работу прятать в `git stash` и возвращать после экспорта
- новые файлы в дереве tdesktop с crlf
- пока локальный `mad.exe` запущен, линковка падает с LNK1104

## ci и релизы

- workflow [.github/workflows/build.yml](.github/workflows/build.yml), запуск вручную: actions → mad windows release
- тег `v<upstream>-mad.<N>`, по умолчанию N это номер запуска workflow. N зашивается в клиент как `TELE_BUILD`, апдейтер сравнивает сначала версию telegram, потом N
- библиотеки и ccache лежат в кеше actions и сохраняются даже при упавшей сборке. первая сборка на новом теге идёт часа 2-3, дальше около часа
- раннер на visual studio 2026 с тулсетом 14.44. сборка идёт через ninja и ccache, без pdb (с pdb линкер кончается по памяти). при `C1060 out of heap space` шаг сам дособирает в 2 и в 1 поток
- секреты репо: `TDESKTOP_API_ID`, `TDESKTOP_API_HASH`, `MAD_UPDATE_KEY`
- релиз публикуется отдельным заданием на ubuntu, ключ подписи в задание сборки не попадает

### текст релиза и «что нового»

- в тексте релиза пишется, что нового появилось в этом релизе, а не что такое mad. описание проекта живёт в README
- текст собирает [ci/mad-changelog.py](ci/mad-changelog.py): берёт строки таблицы `docs/releases.md`, которых не было в предыдущем релизе, и добавляет подвал из [ci/release-notes.md](ci/release-notes.md)
- тот же скрипт пишет `mad-changelog.json`, он прикладывается к релизу. по нему клиент показывает окно «что нового» и после обновления постит изменения в чат mad
- поэтому у каждого нового патча должна быть понятная пользователю строка в `docs/releases.md`: из неё получается и релиз, и окно в клиенте

## автообновления

- апдейтер tele переведён на релизы этого репо: клиент раз в 3 часа читает `releases/latest/download/mad-update-win64.json`
- фид подписан ed25519. открытый ключ в `ci/update-public-key.pem` и в `tele_updater.cpp`, закрытый только в секрете `MAD_UPDATE_KEY` и в бэкапе у ярослава. потеря закрытого ключа значит, что установленные клиенты больше не примут обновлений
- однофайловый `mad.exe` распаковывает клиент в `%localappdata%/mad-single/app/<сборка>`. апдейтер кладёт рядом `mad.exe.updated` с хешем, чтобы лаунчер не откатил обновлённый exe
- локальные сборки (`TELE_BUILD=0`) сами не обновляются

## сервер

- `sync.mad.tg`: зашифрованная синхронизация удалённых сообщений и правок, код в [server](server). шифрование на клиенте, ключ на сервер не уходит
- `b.mad.tg`: подписанные бейджи
- сейчас хранилище выдаёт админ вручную (`node admin.mjs create-vault`). обсуждалась замена без ручной выдачи: синк через скрытый канал в самой телеге, либо авторегистрация с привязкой второго пк по коду. решение не принято

## договорённости

- коммиты по одному на изменение, одной строкой в стиле tele (`feat:`, `fix:`, `ci:`, `docs:`), без соавторов и упоминаний ai
- опубликованную историю не переписывать без просьбы
- нерелизный патч дорабатывается фиксапом в его же коммит, выпущенный новым коммитом
- общение с ярославом на русском, с маленькой буквы
